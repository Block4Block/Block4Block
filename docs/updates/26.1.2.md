# Minecraft 1.21.11 → 26.1.2

The second step towards 26.3, one version at a time (Server Queue SQ2 and SQ45). Started 26 November 2026, right after
1.21.11 went live (SQ52).

## What 26.1.2 adds
Found by comparing the Paper API's block, item and mob lists for 1.21.11 and 26.1.2, not from patch notes:
- **One new block: the Golden Dandelion** (and its potted form). Crafted from a dandelion and eight gold nuggets, or
  bought from wandering traders; fed to baby mobs, it stops them growing. **The owner's choice (SQ53): Free in Claims,
  like the redstone objects** ("a utility block/object"): free and it drops itself in your own claim; elsewhere it costs
  one and drops nothing. The potted one the same.
- No new mobs, so no new spawn eggs or heads.
- Nothing removed.

Other changes that matter here:
- **Java 25** is required (server and client).
- **Worlds move to a new folder layout on the first start.** The Nether and the End move from `world_nether` and
  `world_the_end` into `world/dimensions/minecraft/the_nether` and `.../the_end`; player data moves to `world/players`.
  Paper does it automatically, after a 30-second warning in the log. The worlds keep their names (`world_nether`,
  `world_the_end`), so the plugins that name them (Block4Block's claim contest, B4BClaimAssetCounter,
  AdaptiveRangeMobSpawner, DHSupport) keep working. On the main server: the nightly backup still covers everything
  (the folder `world` now holds all three dimensions), and the datapack stays in `world/datapacks`.
- Data format 101.1.

## Changes
### Block4Block 4.13 (branch `update/26.1.2`)
- **Built against the Paper 26.1.2 API** with JDK 25.
- **No longer needs ProtocolLib.** ProtocolLib 5.4.0 has no 26.x support yet. Block4Block used it in two places only:
  to find the server's player class for disguises (now found directly), and to decide whether to turn on the Master
  Book lectern listener, which hasn't used ProtocolLib since 4.11 (now always on). Without this, removing ProtocolLib
  would have silently switched off disguises and Master Book copies.
- `claimbarbot.js` finds a claim of VetBot's itself (it had fixed coordinates).

- **Golden Dandelion** (SQ53): `GOLDEN_DANDELION` and `POTTED_GOLDEN_DANDELION` in `blacklisted-claim-blocks` and
  `no-loot-on-break`, as for the redstone objects. `breakbot.js` checks it (outside a claim: costs one, drops nothing,
  refused without one; inside your own claim: free, drops itself) and now starts each run on unclaimed land far out.

### Essential datapack (branch `update/26.1.2`)
- `pack.mcmeta` declares support up to data format 101.

**B4BAdvancements:** the 4.4 jar on the main server is not the code on GitHub (Block4Block/B4BAdvancements). The jar
is UltimateAdvancementAPI-generated (`hasjamon.b4badvancements.project`, two tabs) and uses no ProtocolLib or server
internals. The GitHub code is older and different: it reads item names through obfuscated 1.20.1 internals, which
wouldn't work on today's servers. Nothing to change for the update; worth knowing before anyone rebuilds it from GitHub.

## Checked on a copy (Paper 26.1.2 build 74, Java 25, port 25575)
A copy of the 1.21.11 copy, world included, so the world upgrade and folder move were tested too.
- All 16 plugins enable; the datapack loads; no errors in the log.
- `tooltipbot.js` 6/6, `disguisebot.js` 3/3, `lecternbot.js` 4/4, `pluginsbot.js` 8/8, `breakbot.js` 9/9 (with the Golden Dandelion),
  `claimbarbot.js` 6/6.
- New on 26.1.2: "Tooltip hash mismatch" warnings when the bot clicks items. The bot sends a hash of 0 (the bot library
  doesn't compute item hashes); the server then resends the slot, and the bot's item moves still work. A real client
  computes the hash: the owner's real-client check (SQ55) moved items normally, so it is a bot artifact.
- The owner's check (SQ55, 26 November), with the fabric-loader-26.1.2 client: the client and its mods start,
  Distant Horizons and the advancement tabs work, real-client tooltips and item moves are fine, the Nether looks as
  before. "all checks all good".
